# ミスタイプ・複数語完成・ストリーク仕様

状態: ミス判定・複数語完成・読み文字ストリーク・共有入力イベントを実装済み。戦闘効果は未実装。  
更新日: 2026-10-29

## 実装した方針

入力途中のすべての語を並行して照合し、入れ子・同時完成・部分的な重なりによる複数語完成を認める。先に始めた語だけを採用する優先規則は使わない。

一語が完成した時点で全候補を消すのではなく、完成した語を処理し、ほかの語の有効な途中進捗を残す。受信表示の整理、照合状態の保持、IMEの受け口のクリアを別々の責務にする。

ユーザーは「一語ずつ区切り、完成語の文字を次語へ共有しない」という直前の選択を撤回した。複数語完成時のダメージブーストは追加アイデアとして扱い、倍率・適用先などを確定仕様にはしない。

ここでいう二枚抜きは、まず二語の入力完成・二体への標的化を指す。戦闘では敵のHPが残り得るため、実際の二体撃破とは区別する。

## ストリークの単位

ストリークは、ミスせず正しく入力した読みの文字数。単語完成数やローマ字のキー数ではない。小書き文字も1字なので、しは1、ちゃは2、んは1とする。長音記号も読みの1字として数える。

ローマ字は仮名の進捗が確定してから加算する。たとえばtyでは0、tyaでちゃの2字、tyawaで3字、tyawanはまだ3字、tyawannで4字。綴り候補がnとnnに分かれる途中では、どの候補でも確定した読み位置だけを使う。

複数語が同じ入力を使って進んでも、その入力で新たに確定した読み文字を一度だけ加算する。

| 入力 | ストリーク | 共有入力イベント |
| --- | --- | --- |
| ちゃわんがん / tyawanngann | 6字 | 茶碗と湾岸の共有あり |
| ちゃわん＋わんがん / tyawannの後にwanngann | 8字 | この二語の共有なし。＋は説明上の区切りで入力キーではない。 |
| eigo（英語＋囲碁） | 3字 | 同時完成の共有あり |
| pasokonn（パソコン＋底） | 4字 | 入れ子の共有あり |

ミス時に0へ戻す。同じ入力でミスと別語の正しい仮名が成立する場合、先にリセットし、その入力で確定した正しい仮名から新しいストリークを数える。tyawaniの最後のiではミス1回とわに完成が両立し、にの1字から再開する。

## 期待する完成結果

| 単語と入力 | 完成のタイミングと残す進捗 |
| --- | --- |
| 英語 eigo / 囲碁 igo に eigo | 最後のoで両方完成する。 |
| パソコン pasokonn / 底 soko に pasokonn | pasokoで底が完成する。パソコンのpasokoを残し、続くnnでパソコンも完成する。 |
| 茶碗 tyawann / 湾岸 wanngann に tyawanngann | tyawannで茶碗が完成する。湾岸のwannを残し、続くgannで湾岸も完成する。 |
| 絵 e / 英語 eigo に eigo | eで絵が完成し、英語のeを残す。続くigoで英語も完成する。 |

同じ入力で二語が完成する場合だけでなく、入力区間が重なる二語が別のタイミングで完成する場合も対象にする。短い語の完成を長い語の終了まで待たせず、各語は成立した時点で完成イベントを出す案とする。

完成した敵の語は従来の希望どおり入れ替えるが、その変更でほかの敵の進捗を消さない。新しく割り当てた語へ、既に処理済みの過去入力を遡って流し込まない。同じ敵・語の版・入力区間に対する完成は一度だけ通知する。

## 入力保持とUI

「一語が完成したら入力全体を空にする」を、「継続できる候補に必要な入力だけ残す」に置き換えた。全単語に同じ規則を適用する。

| 管理するもの | 役割と扱い |
| --- | --- |
| 照合状態 | 各語の途中進捗。ほかの語の完成で全消去しない。 |
| 画面上の受信表示 | 生きている途中候補が必要とする、最も古い位置から現在までの入力を表示する。不要になった先頭を落とし、候補がなければ空にする。 |
| IMEの受け口・Decoder | Androidとの輸送・変換中状態。従来どおり確定・単語完成時にクリアし、ゲーム内の他語の進捗は保持する。 |
| 診断用sourceText | IMEから届いた原文。表示の切り詰めや二枚抜きのために書き換えない。 |

二語だけが盤面にある場合の表示例:

| 入力時点 | 完成 | 継続する語 | 受信表示案 |
| --- | --- | --- | --- |
| eigo | 英語・囲碁 | なし | 空 |
| pasoko | 底 | パソコン | pasoko |
| pasokonn | パソコン | なし | 空 |
| tyawann | 茶碗 | 湾岸 | wann |
| 続けてgann | 湾岸 | なし | 空 |

ストリークとミス回数を上部へ表示する。通常盤面は8語、2列×4段。入力表記の最大サイズは24dp相当、正式表記は12dp相当へ縮小し、幅と高さに合わせてさらに収める。白背景の上部TextViewは端末のダークモードでも濃い文字色にする。

画面の先頭を切り詰めても、照合に使う入力位置は別途保持する。表示文字数や表示文字列を入力トークンへ戻して判定しない。

## ミスタイプの基本条件

ストロークの有効性、ミスタイプ、語の完成は独立して判定する。ある語の失敗と別の語の完成は同時に起こり得る。

単語候補の一つが脱落しただけではミスにしない。まだ成功させていない現在の入力試行を、どの候補も継続・完成できなくなった時点でミスとする案を維持する。

ただし進捗を持ち越す方式では、「単語の照合開始位置」と「現在の入力試行の開始位置」を分ける必要がある。

### 単語の照合開始位置

その語に一致し始めた位置。eigoの英語はe、囲碁はiから始まる。入力区間の重なりの判定にも使う。

### 入力試行の開始位置

まだ一語の成功で満たしていない入力の開始位置。これをSとする設計案。

1. 次の新しい入力が始まると、その位置をSにする。
2. S以前から継続し、S以降の入力を説明できる候補を、現在の試行の代替候補として扱う。以前の成功から持ち越した候補も、この位置から新しく始まる候補も含める。
3. そのどれかが継続できれば、ほかの候補が落ちてもミスにしない。
4. Sを含む区間で一語が完成したら、現在の試行は成功で終了し、次の入力から新しい試行を始める。他の途中進捗は残す。
5. Sより後から始まった内側の語だけが完成しても、Sから続けている未達成の試行はまだ終了しない。
6. 現在の試行の全候補が入力不一致で失敗したら、ミスを1回記録してストリークをリセットする。その入力を含む後発候補は残し、成立している最も古い後発候補へ試行を移す。後発語が同時に完成した場合は完成も通知する。

これはユーザーの意図そのものを推定する規則ではなく、成功済みの入力を含めたゲーム上の規則。WordMatcherのPath.startと、WordMatchEngineのtrialStartで照合開始と試行開始を分ける。IME観測の内部認識位置も持つが、それを新しいInputTokenへ戻したり未観測キーを追加したりしない。

### 持ち越しは次の語を打つ義務ではない

絵eを完成させた後、英語eigoの候補がeの進捗を持っていても、次に別の語を始めてよい。

たとえば絵・英語・以下ikaがある場合、eに続いてikaと打つ入力eikaでは、絵と以下を完成できるべきである。英語のeを持ち越していたことだけを理由に、kをミスにしてはいけない。eの成功後、次のiから始まった試行には、英語の継続と以下の語頭が代替候補として参加する。

単に「残っている最も古い単語候補を、常に完成させる義務にする」という前案は、このケースでは使わない。

## 元の二例との整合

### 茶碗とわににtyawani

| 候補 | 照合開始 | 最後のiの直前 | 必要な次文字 | iの結果 |
| --- | --- | --- | --- | --- |
| 茶碗 | 最初のt | tyawan | n | 失敗 |
| わに | 途中のw | wan | i | 完成 |

最初のtからの試行は茶碗の完成でまだ満たされていない。iでその候補が途切れるため、茶碗の入力試行に対するミスを記録する。一方でわには完成する。「有効なストローク」「ミス」「わに完成」が同時に成立する。語末のんにはnnが必要という既存ルールを使う。

### サンゴと散歩にsango

sanの時点でサンゴと散歩は同じ入力試行の候補。gで散歩が脱落してもサンゴが継続するためミスではない。oでサンゴが完成し、その試行は成功で終了する。

パソコン／底でも、pasokoで底が完成しただけでは最初のpaを含む試行はまだ満たされていない。パソコンを続けて完成させればミスはない。途中でパソコンを失敗させた場合は、その時点で元の試行のミスを記録する。過去のpaを個別にミスへ変更することはしない。

複数の代替候補が同時に失敗しても、ミスは一つの論理入力につき最大1回とする案。敵の削除などシステム都合の候補消滅は、入力不一致と区別する。

## 特別効果のための共有入力イベント

二語の完成タイミングだけで判定すると、底→パソコン、茶碗→湾岸を拾えない。完成した語の入力区間が重なっているかを判定し、GameInputUpdate.overlapEventsへOverlapEventを返す。

- eigoとigo: 同じ末尾で二語完成。
- sokoとpasokonn: 内側が先、外側が後に完成。
- tyawannとwanngann: 一部の入力を共有し、順に完成。

いずれも成功した二つの入力区間が重なる。「茶碗に失敗し、わにだけ完成したtyawani」は二語完成ではない。

OverlapEvent.completedNowは今回完成した語、completedEarlierは入力を共有する過去の完成語。wordsで両者の一覧を得られる。eigo/igoの同時完成では一つのイベントに今回の二語が入り、茶碗→湾岸では湾岸完成時に今回の湾岸と過去の茶碗が入る。別々に入力した茶碗＋湾岸はこのイベントを出さない。空入力やIMEプレビュー再評価だけでイベントを再通知しない。

このイベントが将来のダメージブースト等の接続点。現在のMainActivityはログへ記録し、効果本体や倍率は適用しない。

ボーナスは検討アイデア。倍率、上限、三枚以上への拡張、ミスとの関係、適用する攻撃をまだ決めない。別時点で完成する場合は二語目の完成まで二枚抜きと確定できないため、先に発射した攻撃へ遡って倍率を付けるか、後続攻撃や一時バフに適用するかも設計事項となる。

また、Repeaterが複数の標的化を受けたときの3発の扱い、同時発射か発射待ち列かは戦闘側の未決事項。

## 処理順の案

1. 現在の試行と各語の照合状態を確認する。
2. 入力を全候補へ適用し、継続・完成・不一致を集める。
3. 試行の成功・失敗を判定し、ミスと完成イベントを独立に確定する。
4. 完成した語を一度だけ通知し、該当する敵の文字を入れ替える。ほかの敵の途中進捗は残す。
5. 完成区間の重なりから複数語完成を記録する。
6. 残った有効候補に必要な入力範囲へ受信表示を整理する。
7. IMEへ必要な応答を返す。未確定通知の再評価を、新たな完成・ミスとして重複計上しない。

## 実装の責務

- WordMatcherは各候補の開始位置と、各認識段階での有効候補・完成・確定した読み位置を保持する。
- WordMatchEngineは試行の成功／ミス、文字数ストリーク、共有区間、受信表示を扱う。他語の途中進捗を全リセットしない。
- GameInputControllerは複製上でプレビューを行い、未確定区間でも完成したら実状態へ一度反映する。表示用inputTextを入力へ再投入しない。
- GameImeEditTextの既存の輸送・削除防止処理は継続する。輸送バッファのクリアと、ゲーム内の他語の照合状態を分ける。
- GameSessionは既定8語の盤面、入力完成のカウンター、該当枠だけの置換を扱う。将来の戦闘では標的化とHPによる撃破を分ける。

候補を統合しても開始位置を失わない。曖昧なローマ字別表記については同じ開始位置の全候補で確定した読み位置を取り、複数語の同一入力進捗は一度だけ加算する。

## IMEとの接続で守る条件

- 入力位置は論理的な履歴上の位置であり、表示文字数・IME通知回数とは一致しない。
- s→sh→しのような変換中の置換を、新しいストローク列として重複計上しない。
- 未観測のローマ字を作らない。KanaObservationは既存の観測制約として扱う。
- だいと→だいどなど、既存ルールで修飾待ちを認める末尾を不一致確定前にミスにしない。
- sourceText原文を保ち、表示用inputTextを入力トークンへ戻さない。
- IMEの受け口をクリアする場合も、ほかの語の照合進捗と必要な入力区間を保持する。実際のキーボード通知との整合は実打鍵で確認する。
- 完成語と後続入力が同じ通知に含まれる場合、後続を失ったり、仮想的なキーを補ったりしない。
