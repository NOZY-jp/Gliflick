# 戦闘エンティティ・武器設計

状態: Drone、Shield Drone、Shooterとミサイル、Warderと回転バリア、Splitterと分離部品を実装済み。固定性能・出現と外形は[EnemyKindsDesign.md](EnemyKindsDesign.md)を参照。
更新日: 2026-11-02

## 目的と範囲

敵・プレイヤー・弾が動き、文字完成で標的へ弾を撃ち、衝突によってHPが変化するシューティングゲームを作る。現行の最小実装・公開パラメーターの出典・拡張の境界は [EndlessCombatDesign.md](EndlessCombatDesign.md) を正とする。本書は他の敵種を含む全体要件を保持する。

本書は、ユーザーが決めた要件、Glyphicaの公開情報から参考にする挙動、このプロジェクトでは簡略化する範囲、未決事項を区別する。公開情報はゲーム内部の実装方式を示すものではないため、クラス構成や物理処理をそのまま再現しない。

## 用語とオブジェクト案

形状・敵の役割・強化形態を一つのIDに押し込まず、別の概念として扱う案を置く。実際のID設計、継承関係、interfaceの切り方は実装前に確定する。

| 概念 | 責務・候補データ |
| --- | --- |
| Player / MainWeapon | メイン武器を兼ねるプレイヤー本体。初期パラメーターはHPのみ。見た目は円の輪郭。 |
| Enemy | 敵1体の実行時状態。敵種ID、バリアントID、形状ID、位置、速度、現在HP、与ダメージ、表示文字などを持つ候補。シールド付き敵は現在シールド値も持つ。 |
| EnemyDefinition | 敵種・バリアントごとの固定値を定義する候補。最大HP、速度、ダメージ等を持たせ、個体ごとの現在HP・位置とは分ける。 |
| Repeater | メイン武器。標的への発射を制御する。初期レベルは1。 |
| Projectile | 弾1発の実行時状態。発射元、位置、速度、ダメージ、当たり判定などが候補。Repeater等の友軍弾に用いる。シューターミサイルはHPと入力語を持つEnemyとして分類する。 |
| WarderBarrier | ウォーダーに紐づく回転バリア。敵本体とは別の所有者付き衝突エンティティ。所有者死亡時に消滅する。 |

現在は`EnemyKind`（役割）、`EnemyVariant`（形態）、`EnemyShape`（外形）を分離。固定値は`EnemyDefinition`、個体の行動は`EnemyBehavior`、耐久値処理は`Durability`へ分ける。EnemyKindはDRONE / SHIELD_DRONE / SHOOTER / SHOOTER_MISSILE / WARDER / SPLITTER / SPLITTER_SHARDで、ティア・形状・突然変異を独立した定義値として選ぶ。各`Enemy`は数値の`size`を持ち、基準半径に掛けた有効半径を衝突と描画で共有する。Droneの中心円はTier1〜4で同寸、外周の円が増えるTier1〜3で全体の半径が広がり、Tier3以降は同じ外半径を保つ。文字と耐力バーは位置だけサイズに追従し、文字サイズとバー寸法は固定する。被弾円はヒット時の有効半径を基準に拡大する。武器は`MainWeapon`契約と個別の設定・発射方式へ分ける。`CombatSession`は共有入力判定の結果からクリティカル率とWord Rushを計算し、`WeaponRuntimeModifiers`として渡す。`WordRushDefinition`に出典が未公開の時間窓・倍率をまとめ、各武器が発射方式に応じて適用する。`EnemySpawnPolicy`は敵定義を選び、`EnemySpawnDensity`は確率的に一回一体の出現を決める。群れ数・出現間隔は持たない。今回確認した公開デモの適応値・Threat予算・特殊/エリート上限をEnemySpawnDifficultyへ分離。MixedEnemySpawnPolicyが種類とティアを抽選し、Droneはボス制約のない時間・レベル依存の独立したティア分布を使う。

## 敵の要件

| 敵 | このプロジェクトでの要件 | 公開情報から参考にする点 |
| --- | --- | --- |
| ドローン | 基本敵で、出現率を最も高くする。プレイヤーへ向かって直進する。低確率で巨大化または加速化する。巨大化はHPを3倍、加速化は速度を2倍にする。二つの強化は同時に付けない。実装では変異の合計確率5%（各2.5%）、巨大化の数値サイズ1.5倍を用いる。ティアごとの円形マーカーは公式Wiki画像をベクターで再現する。 | 公式Wikiもメイン武器へ向かって移動すると説明し、EnlargedはHPを3倍、Hastenedは移動速度を2倍としている。変異率・数値サイズ倍率は非公開。 |
| シールドドローン | ドローンの系統。シールド値を持ち、攻撃を受けなくなるとゆっくり回復する。 | 公式Wikiではドローンの派生敵で、HPと別のシールドバーを持ち、一定時間ダメージを受けないとシールド回復が始まる。Wiki文には時間の数値がないが、公開デモで0.5秒待機・120/秒回復を確認し採用。 |
| シューター | プレイヤーから離れた位置で停止し、ミサイルを発射する。 | 公式Wikiではレベルの端で停止し、耐久力のある弾をメイン武器へ向けて撃ち続ける。画面外から進入して、端から本体半径＋18dpの配置点で停止する。公開デモの10秒周期と初回50〜150フレーム待機を参照する。 |
| シューターミサイル | シューターが発射する。公開デモのShooterCube系に合わせ、HP200/500/1000/2000/6000・接触40/80/160/320/320を採用。7秒の準備後に固定方向へ進む。初期構想のDrone同等という想定を更新した。 | 公式Wikiはシューターの弾を耐久力のある飛翔体として説明するが、ドローンと同じ性能とは説明していない。 |
| ウォーダー | 周囲をゆっくり回転するバリアを展開し、近くの敵を無敵にする。ウォーダー死亡時にバリアも消える。 | 公式Wikiでは向いている方向からのダメージを防ぐ回転シールドと、生存中に近くの敵を無敵にするオーラが説明される。 |
| スプリッター | 4/5/6部品が一体で移動・回転し、一部を破壊すると残部品が残HPを保持して分離する。部品ごとに衝突とHPを持ち、合体中も生存枠へ数える。 | 部品HP350/500/650、接触40と外形はWiki、分離と移動は公開デモを参照。 |

### ウォーダーバリア

- ウォーダーの周囲をゆっくり回転する。
- 無敵で、ウォーダーが死亡すると消える。
- 周囲120°の弾を消す、というのが本プロジェクトの希望仕様。
- 近くの敵へ無敵効果を与える。
- 敵本体ではなくエンティティとして扱う案。

公式Wikiは「現在バリアが向いている方向からのダメージを防ぐ」と説明するが、扇形の角度が120°であることや、弾オブジェクトを消去する実装までは確認できない。120°と弾の消去は本プロジェクト指定。公開デモの範囲300単位を画面換算し、近くの生きた非Warderへ全ダメージ源共通の保護を与える。所有者死亡で即解除し、別の生存Warderの保護は維持する。

## メイン武器と弾

### Repeater

- 今回実装するメイン武器はRepeaterのみ。
- レベル1では、標的に向けて3発の弾を発射する。
- レベルアップで通常強化とサブ武器を選択できる。Repeaterのダメージ・Crit・進化カウント・爆発範囲、4系統各2段階の進化、現行11サブ武器の基本攻撃を実装。詳細は[LevelUpDesign.md](LevelUpDesign.md)。
- 公式Wikiは短いバースト発射を説明する。初期3発はユーザー指定で、2026-10-30に確認した日本語コミュニティWikiにも3発・基本ダメージ35の掲載がある。出典と採用値は[EndlessCombatDesign.md](EndlessCombatDesign.md)。

### 弾の挙動と見た目

- 弾は比較的速いが、目で追える速度にする。
- 見た目は小さな円と細いトレイル。各弾は発射時に決めた方向へ直進し、敵との最初の衝突または画面外で消える。
- 弾は標的へ向かうが、発射元と標的の間に別の敵やウォーダーバリアがあれば、そちらが先に弾を受ける場合がある。
- 標的選択と実際の被弾対象を分け、移動する円同士の相対スイープ判定で最初の衝突を解決する。

## 文字と標的の接続

- 敵は表示文字を持つ。
- 文字を正確に入力すると、その敵がメイン武器の標的になる。
- 標的になったとき敵の文字が別の文字へ入れ替わる。
- `CombatSession`が共有の`WordMatchEngine`と`GameImeEditText`へ接続する。単語完成は撃破ではなく3連射の予約と文字の再割当て。複数完成はFIFOのバースト待ち列で受ける。
- 標的死亡後も予約弾を発射し、入力途中の死体文字だけは既存の入力が完了・失敗するまで追跡する。新しい語頭候補、発射、報酬には使わない。
- 入れ子・同時完成・部分重複による複数語完成とoverlapEventsの接続点を実装済み。共有入力と別々に入力した二語を区別し、複数標的化はFIFOのバースト待ち列で受ける。詳細は[MistypeDesign.md](MistypeDesign.md)。ダメージブースト本体は未実装。

## 参考にする公開仕様と取り込まない複雑性

[Glyphica Wiki](https://alias.black/glyphica/wiki_english.html)はThreatとレベル依存の適応値、特殊/エリートの上限を説明する。以前は式を確認できなかったためThreatを未使用としていたが、2026-11-02に公式WebデモのSpawnerで式と抽選表を確認した。種類の抽選とクラス上限へ採用し、独自のランダム到着密度とDroneの時間・レベル依存ティア分布を維持する。数式・採用範囲・推定値は[EnemyKindsDesign.md](EnemyKindsDesign.md)に集約する。

参考値として、公式Wikiの敵バリアント一覧には次の範囲が掲載されている。新しい敵の固定性能はこの公開表から採用した。

| 参考対象 | Wiki掲載値の範囲 |
| --- | --- |
| ドローン | HP 80〜5,800、ダメージ 40〜210 |
| シールドドローン | HP 100〜2,400、シールド 200〜4,800、ダメージ 50〜250 |
| シューター | HP 300〜7,200、ダメージ 25 |
| ウォーダー | HP 300 |

出典の表は複数のバリアント値を列挙している。本プロジェクトでは最初に必要な種類・バリアントだけを選ぶ。出現密度は独立した`EnemySpawnDensity`の暫定値で、毎tickの確率から一体ずつ出す。群れ・固定間隔の概念は持たない。適応値は公開デモの式を参照する。レベルアップ選択、Repeater強化、11サブ武器と基礎的な状態異常は[LevelUpDesign.md](LevelUpDesign.md)に実装範囲を記載。今回の敵種は実装済み。未指定のStalker/Wurm/Swarmerとボスは今回追加しない。サブ武器の進化は[WeaponEvolutionDesign.md](WeaponEvolutionDesign.md)。

## サイズとティア外形

- `EnemyDefinition.radius`は基準半径、`EnemyDefinition.size`は個体へ渡す数値サイズ倍率、`Enemy.radius`は両者の積で求める有効半径。
- 接触・弾衝突、画面外スポーンの余白、敵本体、被弾円・飛散エフェクトに有効半径またはサイズ倍率を使う。Tier1/2/3の全体サイズは1/2/2.83。Tier4〜7はTier3と同じ2.83。巨大化変異はさらに1.5倍。
- 文字と耐力バーは敵の大きさに合わせて表示位置を離す。文字サイズと耐力バーの幅・高さは敵サイズで変えない。被弾円はヒット時の敵の有効半径から始まり、その半径に比例して120%まで拡大する。
- ティア1〜7のマーカー形状は公式Wiki画像とユーザーの説明に合わせる。中心円はTier1〜4で一定サイズ。Tier2/3は外周リングを足し、Tier4は2・3段目のリング間を塗り、Tier5は中心円相当の穴を開ける。Tier3以降の外半径は同じ。
- ドローンの基本移動速度は5.95dp/s（以前の8.5dp/sの70%）。加速化形態はこの基本値の2倍。
- `DroneTierDistributionPolicy`は開始60秒をTier1のみとし、その後210秒または20レベルごとに分布中心を1ティア進める。各上位ティアの重みはそれぞれ一段階の進行幅で0から滑らかに加える。開始後のレベル補正にも同じフェードを適用する。ボス撃破は不要。6分・レベル1でTier1約1%、Tier2約77%、Tier3約22%となる。個々のスポーンで抽選し、レベルアップ時に既存敵の能力を変えない。公開されていないThreat式を再現したとは扱わない。
- 同時に生存する敵は`CombatConfig.maxEnemiesAlive`で制限し、現行値は16体。満員中は新たな出現を行わないが、グループ出現や固定インターバルには戻さない。

## 実装時の確認項目

- ドローンはプレイヤーへ向かって移動する。
- 巨大化ドローンのHPは基準の3倍、加速化ドローンの速度は基準の2倍で、同時には発生しない。
- シールドドローンは被攻撃停止後にシールドを回復する。回復タイミングと速度は採用値を別途決める。
- シューターは指定条件で停止し、プレイヤーへミサイルを発射する。
- ウォーダーの生存中は範囲内の敵が無敵になり、所有者死亡時にバリアが消える。
- Repeaterは標的に3発発射する。現行の採用値・暫定値は[EndlessCombatDesign.md](EndlessCombatDesign.md)を参照。
- 弾の実際の進路上に敵やバリアがあれば、標的とは別の相手に衝突できる。
- 衝突時に適切なHPまたはシールドが減り、プレイヤーのHPも敵側の攻撃から変化する。
- 敵・弾・バリアの更新と描画を分け、画面座標上の形状だけで戦闘ルールを決めない。
